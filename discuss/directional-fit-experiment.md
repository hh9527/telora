# #193：保留类型信息的失配实验

分支：`fix/193-directional-fit`，基于 `5f481180`。当前是实验原型，不能视为 #193 已完成或可合入。

## 实验范围

将两种情况拆开：

- 不能形成类型的错误仍可将槽标为 Conflicted，例如结构递归、未解析引用等。
- 两个已存在结构类型不匹配时，记录失败约束及两侧槽、位置、诊断，但不因此抹掉两侧类型。

父结构在子结构比较没有产生新冲突后才合并，避免提前合并后丢失实际类型。这仍是在原图上操作，没有复制环境、逐模块隔离或失败后回滚。

结构失配记录仍落在共享 equal 路径，因此影响不止 Fit。契约保护另有明确边界：
`solve_contracts` 在加入值证据前检查骨架闭合，记录声明契约是否就绪，并遍历已就绪
契约的结构及 nominal 成员建立保护标记。后续合并代表槽时保留该标记；特殊错误和
继承的 Conflicted 也不能覆盖这些骨架。普通局部推导槽不因第一次获得结构而变成契约。

## 已验证的改善

独立语言资产位于 `tests/language/src/check/diag-shared-contract/` 和 `diag-contract-local/`，内部状态由 `type_resolve/tests/contracts.rs` 检查。

| 观察 | main | 实验分支 |
| --- | --- | --- |
| 错误调用后的共享 increment 签名 | Conflicted | 保留 Fn(Int) -> Int |
| 健康模块的 answer | Conflicted | 保留 Int |
| 连续传入 String 和 Bool 的两次错误调用 | 仅第一次报告 | 两次分别报告 |
| 输入字符串变量 | 可能沿共享约束污染 | 保留 String |
| 失败 MIR 的 seal | 拒绝 | 仍拒绝，清除诊断文本后也拒绝 |

新断言还验证了：交换导入顺序、同模块泛型错用与正常实例共存、合法未注解调用继续推导，以及函数体违反已声明返回类型仍然失败。
