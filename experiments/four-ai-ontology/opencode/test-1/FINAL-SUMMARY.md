## 一、实验设计

验证"知识通过文件在隔离 AI 角色间分层传递 + Telora 验证闭环驱动收敛"在 opencode 中成立。

```text
主 Agent（推进/验证/诊断中继/规范验收）
A2: R(a1)          RW(a2)   # 实现 ontology eDSL
A3: R(a1+a2)       RW(a3)   # 建模航班运营企业
A4: R(a1+a2+a3)    RW(a4)   # 查询（测试者/攻击者）
```

核心约束：Agent 不执行 telora（主 Agent 代执行并转发诊断）；A4 必须走 `model.compile`
（协议强制，不能绕过构造计划）；同一模型。

## 二、各 Stage 结果

### Stage 2 — A2 实现 eDSL
- 12 轮诊断，A2 反复撞 Telora 泛型推断边界（泛型函数参数退化为 Any），问题逐个转移。
- A2 独立贡献：types/ontology 通过 check、三份文档、二分发现（PathReport 红鲱鱼、
  Relation 透传、纯透传要求）、诚实申报异议。
- 主 Agent 用 /tmp 大规模复现定位"魔法"：选择性导入退化 + 参考 CPS 形状。
- 结果：主 Agent 用参考形状补 compiler（用户选项 1）；微模型验收通过。

### Stage 3 — A3 建模航班运营企业
- 2 轮收敛（enum 语法 + 依赖路径）。模型 + valid/invalid 全部通过，跨层诊断工作。
- 关键对照：A3 使用 DSL 2 轮 vs A2 实现 DSL 12 轮——"使用远易实现"被实测。

### Stage 4 — A4 查询/攻击
- 6 类 trial：合法/新奇 → lowered；未知能力/fan-out/未授权 → refused。
- 协议强制验收通过：A4 看到完整实现但全部走 model.compile，未绕过。
- A4 攻击发现 4 个真实缺口。

## 三、逐层反馈闭环

| 缺口 | 层 | 修复 | 验证 |
|---|---|---|---|
| 导出面可绕过 | A3 | 只导出 compile | ✅ |
| 空请求发布空计划 | A3 | 入口拒绝（带 subject） | ✅ |
| 重复请求不去重 | A3 | 入口去重 | ✅ |
| fan-out 未进发布门 | **A2** | 门加 fanOutOnly==0 | ✅ |

缺口 3 由 A3 明确判断属于 eDSL 发布契约，上升 A2 修复。全部回归通过。

附带发现：`emit_error!` 零 subject 触发 Telora 运行时 panic（RFC 0187 声称合法）——
语言层 bug，A3 用带 subject 绕开。

## 四、关键发现

1. **Telora 泛型推断边界（最重要）**：
   - 选择性导入（`{ func }`）使泛型调用退化为 Any，命名空间导入正常；
   - 可工作形状极度特定（CPS + 带 Input + idOf 返回 Id + 无包装闭包 + 分类无 eq）；
   - 可发现性极低——独立作者 12 轮 + 模式提示未收敛，主 Agent 大规模复现才定位。
   这是 Telora 的工程缺口，应反馈语言层。

2. **eDSL 消费侧可用性成立**：A3 用 DSL 2 轮收敛（对比 A2 实现 12 轮）。

3. **跨层诊断工作**：缺失/粒度扩张/未授权都带 model 规则 + eDSL 规则双来源。

4. **知识归属正确性在修复环节实证**：去重/导出归企业（私有知识），发布契约归 eDSL
   （通用机制）——缺口精确落在它该在的层。

5. **协议强制边界成立**：A4 看得到实现但必须走接口——边界是"唯一合法通道"而非"看不见"。

## 五、实验价值与边界

**价值**：四层知识传递链（语言 → eDSL → 企业模型 → 查询边界）端到端走通；暴露语言层
（推断边界、emit_error bug）和模型层（发布契约、导出面）的真实可改进点；验证"攻击者 +
逐层反馈"作为设计质量闭环的有效性。

**边界（诚实）**：
- compiler 由主 Agent 补（选项 1），clean-room 纯度打折——A2 独立实现止于 types/ontology；
- 单模型（flash）、单领域、单次运行——不证明普遍性；
- A2 的实现困难部分归因模型（flash 弱于更强调模型）部分归因 Telora 边界（可发现性低）。

## 六、与整个探索的关联

- "使用 DSL vs 实现 DSL"门槛差，印证 eDSL 消费侧是它真正的价值所在；
- Telora 泛型推断边界是"有限 GPL"路线的真实摩擦点，值得反馈语言层；
- 攻击者 + 逐层反馈完美体现"度量回报率"方法论——让攻击者实测、按层归因修复；
- 四层链正是 Telora"意图编译"哲学的完整实例化：意图从人出发，经层层降级，最终在边界内
  变成可信计划，边界外被可诊断地拒绝。
