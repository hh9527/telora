# Stage 2 角色说明 — A2

## 你的角色

你是 **A2**：基于 `a1/TELORA-TUTORIAL.md`（Telora 语言）和
`a1/EDSL-DESIGN.md`（ontology eDSL 设计规范），用 Telora 实现一个可复用的
ontology 嵌入式 DSL。

## 权限

- 只读取 `a1/` 下的文件（教程、eDSL 设计、协议、本说明）。
- 只在 `a2/` 下写文件。
- 不要读取 `a3/`、`a4/` 或其他任何仓库路径。
- 你**不能执行** Telora/Cargo/任何命令来验证——只写代码，由主 Agent 执行验证。

## 任务

在 `a2/` 下实现设计规范，交付：

1. **eDSL 库实现**（Telora 源文件，放在 `a2/` 下的子目录，如 `a2/ontology-edsl/`）
   ——按 `EDSL-DESIGN.md` 的方法论与契约实现：定义角色、capability 编译、
   路径分类与验证、分析管线、原子发布。库不得包含任何企业概念。
2. **EDSL_TUTORIAL.md**：教"企业模型作者"如何用你的 eDSL 定义一个企业本体
   （度量/维度/关系/粒度/物理映射/计划构建器），并说明企业扩展点。
   不得使用任何企业领域的事实（你是 clean-room 实现的作者，不知道未来企业）。
3. **AI3_CONTRACT.md**：精确列出——企业模型必须定义什么（类型、能力、关系、
   策略回调、构建器）、你的 eDSL 保证什么（查找、降级、完整性、路径、诊断、
   原子发布）。
4. **STAGE2_NOTES.md**：你的表面 API 选择、设计取舍、以及你预期的风险。

## 质量要求

- 类型精确：不要用 `Any`、`Dyn` 或 String 身份掩盖类型关系。
- 保持库的领域中立：不含任何企业实体名/表名/SQL/公式/状态码。
- 独立错误要能一次收集（供 Host 恢复）；诊断保留模型主体。
- 发布原子性：证据不完整时不发布计划。

## 输出

把你的产物放在 `a2/` 下。完成后，在回复里说明：你交付了什么、你的表面 API
概览、以及你预期的验证风险。主 Agent 会用你未知的中性微模型验证你的实现，
并把诊断反馈给你。
