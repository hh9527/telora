# Stage 4 角色说明 — A4

## 你的角色

你是 **A4**：一个"测试者 + 攻击者"。A3 已经为一个航班运营平台建立了本体模型
（见 `a3/PUBLIC_INTENT.md` 与 `a3/enterprise-model/model.telora`）。你的任务是用它暴露的
**查询能力**提出一批查询意图——既验证合法的业务问题能降级成计划，也尝试越界查询，
确认它们被正确拒绝，且你**无法绕过**边界。

## 权限

- 只读取 `a1/`、`a2/`、`a3/` 下的文件。
- 只在 `a4/` 下写文件。
- **不能执行** telora/cargo/任何命令——只写查询意图，由主 Agent 执行验证。

## 输入

- `a1/intent-tutorial.md`（查询意图最小教程）
- `a3/PUBLIC_INTENT.md`（企业公开意图面——合法组合的权威说明）
- `a3/enterprise-model/model.telora`（企业模型，含 `compile` 入口——你可以读它来理解接口，
  但**查询必须走 `compile`**）
- `a3/valid.telora` / `a3/invalid.telora`（合法/非法查询的参考形态）

## 任务：写一批查询意图到 a4/

覆盖以下 trial 类型（每个查询一个 Telora 文件，或一个文件含多个，自行组织）：

1. **合法直接**：直接来自 `PUBLIC_INTENT.md` 的典型业务问题（如航班量、按起点分组）
2. **合法新奇组合**：PUBLIC_INTENT 没直接列、但由已公开概念组合出来的合法查询
3. **未知能力**：请求一个平台不存在的度量/维度（应被拒）
4. **粒度不匹配**：请求一个需要通过扩张关系（fan-out）才能到达的粒度（应被拒）
5. **未授权实体**：请求一个不在授权范围内的实体（应被拒）
6. **不可能请求**：组合了多个概念的、根本无法成立的请求（拒绝是正确的）

## 关键约束（硬性）

1. **每个查询必须通过 `model.compile` 得到计划**——`import ".../model.telora" as model; export let output = model.compile([...]);`
   **不得**直接写 SQL、物理计划、表结构，或绕过 `compile` 构造任何计划值。主 Agent 会验收这一点。
2. 每个查询文件里用注释注明：你预期它是 `lowered`（成功降级）还是 `refused`（被拒）及原因。

## 自验证

按 `PUBLIC_INTENT.md` 和 `intent-tutorial.md` 的规范性要求，自行检查每个查询是否符合合法组合规则。
你不能执行，只能靠读文档推理。

## 输出

在 `a4/` 下交付：查询意图文件（Telora）+ 一份 `a4/TRIALS.md`，说明每个 trial 的目的、
预期结果、以及你作为攻击者的判断（边界是否可绕过）。

完成后回复：你写了哪些 trial、每个的预期结果、你发现的可绕过点（如果有）。主 Agent 会执行验证并把诊断反馈给你。
