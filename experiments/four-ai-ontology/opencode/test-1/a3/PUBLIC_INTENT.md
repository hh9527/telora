# PUBLIC_INTENT — 航班运营分析平台（公开意图面）

本文档面向未来查询方（A4）与外部调用方：说明本平台**能回答哪些业务问题**、
**合法组合方式**，以及**顶层编译入口的形状**。

## 1. 平台能回答的业务问题

以"航班量"为核心的运营分析：

- 航班量总体（全部航班的数量）
- 航班量按航线起点（`RouteOrigin`）分组 —— 即每个起点机场对应的航班数
- 航班量按机型（`AircraftType`）分组 —— 即每种执飞机型对应的航班数

平台在语义上保留了"登机旅客数"（`Boardings`）与"航空公司名"（`AirlineName`），
但二者均有额外限制（见下）。

## 2. 合法组合方式

一次编译请求是一组**能力意图**（`Measure` 枚举中的请求身份），来自以下集合：

- 度量：`FlightCount`（航班量）
- 维度：`RouteOrigin`（航线起点）、`AircraftType`（机型）、`AirlineName`（航空公司名）
- 登机度量：`Boardings`（登机旅客数）

组合规则：

- **度量 + 维度**可组合，例如 `FlightCount` 与 `RouteOrigin` 一起请求即得到
  "航班量按航线起点分组"；`FlightCount` 与 `AircraftType` 一起请求即得到
  "航班量按机型分组"。
- 只请求 `FlightCount` 得到总体航班量。
- 请求列表中的**每一项都必须有对应能力**：请求平台不存在的度量（如 `Revenue`）
  会报"缺失能力"诊断，整次编译失败。
- **粒度规则**：维度/度量所需的粒度必须能从基准粒度（航班 `Flight`）经**安全路径**
  到达。`Boardings` 的自然粒度在座位（`Seat`），而从航班到座位是**扩张路径**；
  直接请求 `Boardings` 而未提供预聚合会被拒绝（粒度扩张诊断）。
- **授权规则**：所需粒度必须在授权范围内。`AirlineName` 涉及的外部航空公司数据
  不在授权范围内，相关查询会被拒绝（未授权诊断）。

## 3. 顶层编译入口形状

平台导出一个编译入口（企业模型模块 `enterprise-model/model.telora`）：

```
compile(requests: Array(Measure)) -> Option(Plan)
```

- `requests`：一组能力意图身份（`Measure` 枚举值）。
- 返回 `'Some(plan)` 表示编译通过、发布成功；返回 `'None` 表示被拒绝
  （伴随一组诊断，如缺失能力 / 粒度扩张 / 未授权）。

顶层验证文件的写法：

```telora
import "./enterprise-model/model.telora" { compile };
export let output = compile(['FlightCount, 'RouteOrigin]);
```

## 4. 平台保证

- **原子发布**：任一请求缺失能力、任一所需粒度未授权或不可达、或构建策略拒绝，
  整次编译都不会发布计划（`'None`）。
- **诊断先于发布门**：被拒绝时，具体原因（哪项能力缺失、哪个粒度扩张、
  哪个粒度未授权）都会作为诊断产出，不会被发布门掩盖。
- 编译产出是**惰性计划**（描述性结果），不是执行授权；本面不描述其内部构造。
