# RFC 0288：服务边界 work-world 复制回收

- 状态：后续阶段草案；不在本期 eval-with 交付范围，不实施
- 日期：2026-09-12
- 上级：[RFC 0282](0282-native-cranelift-roadmap.md)
- 分支：`feat/native-cranelift`
- 跟踪：本期不创建实施 issue，待持续服务阶段启动

## 动机与范围

采用请求边界回收，避免执行期间持续自动 GC。

## 用户可见语义与内部契约

本 RFC 不改变语言语法和静态求解规则。新增执行能力仅经隐藏 native 路线选择；默认旧实现不变。

- eval/eval-with 默认只分配，结束后整体释放；run/serve 在安全服务边界按请求次数或分配量触发回收。
- 明确跨请求根集合、host 持有引用和缓存保留政策；无根直接清空/替换，有根复制可达图到新 work-world。
- 以旧 world + 表类别 + HeapId 为转发表键，先登记再遍历以处理环；保持对象共享、TypeId、来源以及 main 引用不变。
- 回收时不得存在旧 world 的活动执行帧或未登记借用；并发采用每执行上下文独立 world 或明确静默点，具体方案实现前定案。
- native resource 明确可复制/迁移/拒绝的类别及唯一析构责任；复制失败保持旧 world 可用，不发布半迁移状态。
- 长时间单次请求可能持续增长，服务边界回收不能解决该情况；先明确限制，不引入中途 GC 作为隐式补救。

## 实施计划

先落实本模块契约并保证可独立编译，再用简单单测或少量语言用例验证，然后进入后继模块。允许 native 路线阶段性缺失能力，不要求每次提交完成整个语言。实现前将本草案中的待定项补成明确决议，不引入兼容兜底。

## 验收条件

验证空根、共享子图、环、main 引用、跨请求状态、资源恰好释放一次、迁移失败原子性和连续多轮请求内存回落。记录分配量、存活量和回收耗时；总装完成后用真实 ontology/model 工作负载观察性能。

## 延后与备选方案

不采用 Wasm/Wasmtime、多层编译链或新字节码解释器作为本阶段前置。不提前替换默认运行时。性能优化、AOT 分发、跨平台覆盖与生产切换按证据另立后续 RFC；本子项完成不等于新路线全量验收。
