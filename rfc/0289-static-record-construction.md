# RFC 0289：封闭的记录构造与移除 cast

- 状态：已实施
- 决议来源：用户确认匿名 Record 不应成为最终值类型，cast 为动态类型阶段遗留，彻底移除
- 分支：`feat/native-cranelift`

## 契约

`{...}` 提供待求解的字段构造信息，最终值必须确定为具名 Struct 或 `Dict(T)`。
内部可以保留结构证据，但它不是可发布的匿名 Record 类型，不能进入运行时。
类型上下文来自整图求解，未标注的局部声明不自动冻结成匿名类型。
缺少充分证据时在静态阶段诊断，不由 codegen 或 VM 猜测类型。

同一个泛型参数 T 的所有出现必须归一为同一个 TypeId。两个不同的名义类型
不能因字段相同而共享 T，也不在运行时重新标记身份。

删除 `cast!` 的前置与后置语法、AST/HIR、求解规则、LIR/字节码和两套运行时实现。
不保留兼容入口。静态类型约束使用标注或 `ty!`；外部 Value 解码使用 codec；
Dyn 使用精确投影。这些操作各有明确契约，不重新实现一个通用 cast。

## 实施与验收

先完整删除 cast 链路和相关正向测试，保留未知 intrinsic 的负向语言测试。
数据示例改用 codec，原有构造检查测试继续覆盖普通构造与 Unchecked 完成边界。
随后取消记录证据的提前冻结，确保全图槽位统一，并禁止未定记录成为最终值类型。
更新语言文档及旧匿名类型测试，覆盖上下文传播、缺少上下文、不同名义身份冲突。
最后验证默认及 native check/eval/eval-with；不增加运行时兼容路径。

## 实施结果

- `3bfcbd3` 删除 cast 的完整链路，保留前置、后置语法的拒绝测试。
- `37deb1d` 删除记录证据的提前物化标记，使后续全图上下文仍可统一类型。
- 类型诊断与 seal 共同拒绝没有 Dict 或具名 Struct 上下文的记录构造。
  内部 Record 仍用于类型骨架、模块导出清单和 `<~` 字段证据，不代表用户值类型。
- 默认和 native codegen 直接消费 `<~` 的字段输入，不构造临时匿名 patch 值；
  保留源码求值顺序及最终构造检查。
- 语言资产改用明确的具名类型或 Dict 上下文，新增缺少上下文、投影缺少上下文、
  不同名义类型不能共享 T 的负向用例。

验收：core 346 项、native 138 项及 3 项集成测试、408 个语言验收用例通过。
world-model 全模块纯类型检查 Unknown/Conflicted 均为零；真实 native eval-with
查询成功，输出与默认路径逐字节一致。本次不重新做性能评估，也不表示 native
伞 RFC 的所有工作已经完成。
