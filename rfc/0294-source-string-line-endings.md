# RFC 0294：源码字符串的实际换行统一为 LF

- 状态：已接受，实施中
- 日期：2026-09-14
- 修订：RFC 0293 中保留多行字符串原始 EOL 的边界

源码中的 CRLF、LF、单独 CR 在字符串文本中统一产生 LF。这适用于普通
String、raw String、带 delimiter 的 raw String、插值字符串的文本片段，
以及 Bytes 字面量中的实际换行。raw 的含义是禁用转义和插值，不是保留
检出平台的换行编码。

规范化发生在字面量文本解码时。显式 `\r`、`\x0D`、`\u{D}` 保留 CR，
不能在转义解码后对整个结果统一替换，否则会误改显式构造的数据。
反斜杠续行接受三种源码 EOL，仍移除换行及随后的空白。
CST 和来源范围保留原始文本，数据模块/运行时输入遵守各自数据格式语义，
不因本规则进行全局字符串替换。

验收使用独立语言测试覆盖各类字面量、插值、续行以及显式 CR；整套语言
资产检出为 CRLF 后直接交给编译器。另验证包含多行字符串的源码在三种
EOL 下生成相同 Wasm 制品。测试资产不依赖 `.gitattributes` 强制 LF。
