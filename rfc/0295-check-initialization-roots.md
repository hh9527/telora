# RFC 0295：check 多根初始化与顺序失败传播

状态：已实现。
关联：#137；替代此前文档中的容器失败槽位及 run best-effort 语义。

## 决策

静态求解按整图收集诊断，不执行用户代码。类型闭合后，check 对所选模块的具体顶层
声明及所需 property 初始化进行多根求值。当前 seal_modules 保留所有具体顶层声明，
包括非导出辅助声明；本次不改变根的选择，只改变根之间的失败调度。

每个根内部采用顺序失败传播。let initializer、普通函数、跨模块调用、闭包或容器
逐项求值失败后，当前调用立即退出，后续表达式和 callback 不执行。
共享依赖使用现有 demand 状态缓存，失败状态保留同一原始诊断，不重复报告。
check 继续尝试其他根，但任何未消费 error 都阻止 freeze 和成功发布。
引擎 trap（包括 fuel/内存限制）仍立即终止初始化，不恢复或重置配额。

run/serve/eval/eval-with 的初始化仍为首个失败即停止，失败时不进入 entry。
删除 run/serve 的 --best-effort 参数，不保留兼容分支，也不额外预执行用户代码。
服务已有的单请求恢复和显式诊断捕获边界不变。
test 初始化仍为严格模式，成功后才在独立测试用例之间恢复失败。

## 实现与验证

Wasm codegen 为 check 提供专用编译入口，共用类型、布局、函数生成及 demand 缓存。
仅初始化驱动代码继续遍历 demand；普通函数中的失败检查不变。
沿用当前 demand 的稳定顺序，成功任务不重算，失败 session 不进入冻结阶段。

独立 .telora fixtures 覆盖本地、跨模块、facade 和闭包转发；CLI 回归检查四个根因
各出现一次、共享失败不重复、顺序 continuation 不执行、check 最终失败，以及
only-types 不执行和 eval 严格停止。CLI 表面测试确认已移除参数被拒绝。
历史 ontology A4 场景不作为本次验证依据；当前最小复现不依赖外部工程。

验证结果：95 项 CLI 回归通过；语言测试全集通过。全集曾发现 test 复用 check 编译
入口导致初始化策略外溢，现已显式分离 check/tests 调度，并保留原语言验收预期。
