# RFC 0301：interpreter! 使用普通高阶函数与闭包语义

- 状态：独立分支已实现并验证，待合入
- 跟踪：[#210](https://github.com/hh9527/telora/issues/210)
- 分支：`feat/210-interpreter-ordinary-closures`
- 日期：2026-09-17
- 修订：替代 interpreter! 的 wrapper memoization、重复适配身份复用及 operand 延迟求值规则；保留静态类型准入与 Dyn 安全包装规则

## 动机与范围

interpreter! 是受信任的高阶适配器：取得一个函数，返回捕获该函数的普通闭包。
编译器根据已封闭类型生成参数包装代码，运行时不需要特殊缓存或类型推断。

历史实现最初把 operand 放进内层函数体；提交 9f104da0 又增加按外层闭包身份及
类型参数复用 wrapper 的语义。Wasm 在 2f39929b 延续该规则，把缓存放入外层闭包环境。
这使请求中首次适配可以修改初始化环境，并留下指向请求期数据的引用。

本 RFC 显式撤销这些特殊规则，为后续单 Vec 语言堆及 work_base/truncate 奠定基础。
本次不改语言堆、不更换分配器，也不移除服务的线性内存快照恢复。

## 用户可见语义

以 `for(T) Fn(TypeOf(T)) -> Fn(T) -> R` 为例，概念展开为：

```text
let f = operand;                       // 构造 interpreter! 值时求值一次
fn(witness) {                         // 普通外层闭包，捕获 f
    fn(value) { f(pack(witness, value)) } // 普通内层闭包
}
```

示意中的类型和 pack 由封闭 MIR 决定，不新增用户可见语法或运行时类型判断。
operand 的诊断和失败发生在构造适配器时，即使返回函数从未被调用也是如此。
内层调用只调用已经捕获的函数，不重新执行 operand 表达式。
多类型 witness、非解释参数直接透传以及结果不能包含被解释类型等准入条件不变。

每次调用外层工厂生成普通的新闭包，不再保证相同工厂及 witness 重复调用所得函数相等。
同一个闭包值的复制、赋值和引用仍保持普通函数身份；不同捕获实例不能被合并。
这是有意的语义变更，不保留旧缓存兼容路径。

## 实现

构造 interpreter! 时在当前词法环境求值 operand，将得到的普通函数值作为唯一捕获。
外层工厂取得该函数，构造内层闭包；内层同样只捕获该函数。捕获的是函数值引用，
不深复制其环境。适配代码入口走现有编译计划和链接过程，不引入专用稳定 ID 机制。

删除 interpreter! 专用缓存槽、读取和回写。删除仅为它存在的 raw-parent 环境标志、
父环境地址映射以及 frozen 环境 memo-cell 回收修补。普通闭包环境按值引用遍历。
内部 ABI 版本随环境表示变更更新，禁止新 RT 误消费旧表示。

来源元数据仍独立保留 `id, name_ptr, name_len, bols_ptr, bols_len`，不在本次改动范围。

## 实施与验收

1. 提交 RFC，更新 #210 为新的语义目标，历史 RFC 只添加覆盖说明。
2. 修改 codegen/RT，去掉缓存及专用追踪分支，同步当前 LANGUAGE/CONCEPT 文档。
3. 优先使用独立 .telora 用例验证：operand 构造时只执行一次、未调用也求值、
   构造失败的诊断时机、重复适配的新身份、同一值引用的身份、多 witness 和局部捕获。
4. 验证初始化工厂在请求中调用、保活适配闭包经过 copy-collect 后再次调用；
   运行 Wasm/语言测试及 lab-ontology 的真实路径。
5. 阶段性提交并推送独立分支，在 #210 记录证据。不在此合入单 Vec 堆改造。

## 备选与取舍

- 保留缓存并在 reset 时清空：增加前缀写入及恢复协议，拒绝。
- 为适配器额外设计固定身份：把历史复用要求继续带入新实现，拒绝。
- 提前构造全部 wrapper：没有必要；采用普通闭包分配，后续根据测量再优化。
- 保留 operand 的延迟求值：与传入函数的高阶模型不一致，拒绝；需要延迟的用户逻辑
  可以显式放在输入函数体内。

## 实施结果（2026-09-17）

- 工厂和适配器均捕获已求值的普通输入函数；移除缓存、raw-parent 环境、父环境
  地址映射及冻结环境缓存修补，内部 ABI 更新为 22。
- 独立 .telora 用例覆盖构造期一次性求值、未调用也产生诊断、构造期失败、
  普通闭包身份、多 witness、透传及局部捕获。Rust 只保留执行、内存边界和 GC 驱动。
- 87/87 Wasm 测试通过；增加初始化环境逐字节不变断言后，相关测试再次通过。
  84/84 CLI 测试（含完整语言套件）、27/27 库/LSP 测试通过。
- release 构建成功；ontology `check --lib` 通过，world-model
  `run @src/bin/make-query` 返回预期 Asia 参数及 SQL，无需修改 lab-ontology。
  该项目当前未直接使用 interpreter!；它验证整体兼容性，专门语义由语言用例覆盖。
- 单次并行 smoke 观察：check 约 0.78 秒，query 约 0.72 秒；query fuel 4,426,101，
  Guest 线性内存 1,376,256 字节。未做交替基准，不据此宣称性能收益。

后续单 Vec RFC 还须核实 codegen 的顶层/property demand 状态槽及其引用根，
本次只证明 interpreter! 不再回写初始化环境，不宣称现有整个运行时已实现 service 唯一根。
