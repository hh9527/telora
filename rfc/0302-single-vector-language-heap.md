# RFC 0302：单 Vec 语言堆与保守初始化根集合

- 状态：已实现并验证，已合入 main
- 跟踪：[#211](https://github.com/hh9527/telora/issues/211)
- 分支：`feat/rfc-0302-single-vector-heap`
- 日期：2026-09-17
- 前置：RFC 0301（普通 interpreter! 闭包，已合入 main）
- 关联：RFC 0300（来源范围、Host/Guest ABI 与 std 分配器）
- 范围：语言堆存储、初始化后移动回收、请求生命周期；不修改 property 查询接口

## 动机

用一个 `Vec<u64>` 保存结构化语言对象，另用 `Vec<u8>` 保存 String/Bytes 内容，
通过 raw_start 标识共同的内容分配并提供共享切片，不维护独立 RawBytes 表。
执行任何 .telora 代码前建立固定元数据前缀，
以 `static_end` 标记；初始化后以 `work_base` 划分保活值和请求临时值。
请求只向后追加，正常结束后回收后缀，复用已有容量。

只从 service 的闭包环境追踪还不足以覆盖现有程序：函数代码通过稳定 Id 访问顶层值，
property 查询也可以接受运行时的 Type 值。ontology 的 `Array(Type)` 遍历和字段反射、
std/fmt 的嵌套展示准备都依赖这种能力，不能假定所有查询目标已是静态类型参数。

本 RFC 采用保守根集合，先保证完整保活和移动正确，不做函数依赖精确分析、property
值流分析或初始化结果的最小裁剪。保留额外初始化结果是明确接受的空间代价。

## 现状与语义边界

当前 `SealedExecutable::seal_export` 将全部 concrete property/check 加入初始化根，
codegen 将其加入 demand，并在初始化时主动遍历这些 demand。函数读取结果仍经过
初始化状态槽；这不等于请求中一定会首次求值它们。

类型求解只记录 property 存在性，`Property(P)` 约束不求值 property。
类型的存在不构成属性值读取。现有初始化选择偏宽，是独立的后续改进点。

本 RFC **不改变当前制品选定的初始化集合、求值顺序规则或诊断行为**，不借堆改造
引入“只求值实际读取的 property”的语言变化，也不新增请求期惰性 property 缓存。
初始化期间保留既有依赖求值、环检测与错误传播；成功发布时所选初始化槽必须完成。
若审计发现请求能访问尚未完成的初始化槽，应先修正初始化闭合，不能悄悄回写冻结前缀。

动态 `get_type_prop/get_field_prop/get_variant_prop` 与静态 evidence 接口继续存在。
属性缺席仍按各自接口返回 None 或遵循 evidence 的静态保证，不因根策略改变。

## 存储与引用

概念结构：

```rust
struct LanguageHeap {
    words: Vec<u64>,
    content: Vec<u8>,
    static_end: usize,
    work_base: usize,
    work_content_base: usize,
}
```

```text
[ 固定元数据 | 保留的初始化对象 | 当前请求追加的对象 ]
0           static_end        work_base             len
```

长期对象引用采用堆内偏移，不使用 Vec 底层地址。实施中采用 u32 字节引用：
`origin + byte_offset`，其中 origin 是链接后不可移动静态镜像的对齐末端；小于
origin 的非零引用表示静态区地址，0 保留为空引用。动态引用由当前 words 基址
加上 byte_offset 得到访问地址，对象内部仍使用布局给出的字节偏移。
这不是物理地址兼容路径：所有动态语言引用都必须转换，Host 缓冲区明确走独立接口。
容量、对齐和地址换算均做溢出检查；可编码的 words 字节数不超过
`u32::MAX - origin`，不能把 u32 容量误认为可容纳 u32::MAX 个 word。

Vec 扩容可能移动整个缓冲区。codegen 的局部值引用、对象表 payload、捕获环境、
初始化槽和 RT 跨调用参数都必须使用可重定位的表示。读取字节时由当前基址转换；
不得跨可能分配的调用保留裸指针、slice 或 Rust 借用。不能只替换 allocate 的实现。

保留当前 Loc 的三个 u32、TypeId。除下述 String/Bytes 存储及切片引用外，
不在这里重新设计其他值宽或 pack/unpack。
第一版可以保留分类对象表及现有对象 Id，用表项指向 HeapId；不要求同时把所有表
合并为一种对象格式。表的 len/frozen 基线仍须与堆边界一同维护。

std 的 wasm32 默认全局分配器不变。`mem-alloc/realloc/free` 继续管理 Host 交换缓冲区，
不进入语言堆。Wasm 线性内存、Rust 分配器的堆、语言 Vec 是不同层次。

## 字节内容与共享切片

`content: Vec<u8>` 只保存原始字节，不包含需要 GC 扫描的对象引用。
RawBytes 只表示内部的一次内容分配，不是用户态 Bytes，也没有独立表项或长度头。
非内联 String/Bytes 保存三个 u32，均为 content 内的绝对字节偏移：

```text
String/Bytes -> { start, end, raw_start }
raw_start：所属内容分配的起点，用于回收时分组去重
start/end：当前视图的可见范围 [start, end)
```

同一次分配的所有派生切片沿用同一 raw_start，不同存活分配的起点不重用。
不变量为 `raw_start <= start <= end <= content.len()`；构造时建立合法范围，后续
切片只能在原视图范围内收窄，不能仅凭 content.len() 允许跨越分配边界。
String 可见范围必须是有效 UTF-8，并满足字符串操作的字符边界规则；Bytes 可以
引用任意合法字节范围。转换仍遵循既有检查语义。

内容构造完成后只读。切片只构造新的视图，不修改 content。
所有范围加法、长度转换及容量检查必须防止溢出；空切片也必须有明确、可验证的表示。
没有跨 Vec 扩容保留的 content 裸指针，访问时根据当前基址和偏移取得借用。

回收采用先汇总、后复制的两步流程：遍历全部存活字节视图，以旧 raw_start 分组，
汇总 `lo = min(start)`、`hi = max(end)`，并记录目标对象中待修补的切片位置。
每组只复制一次 `[lo, hi)` 到新 content，记新起点为 base，然后更新组内每个视图：

```text
new_raw_start = base
new_start = base + (old_start - lo)
new_end   = base + (old_end   - lo)
```

首版保留的是所有存活切片并集的包围区间，不是精确的多段并集。它能裁掉无用的头尾，
但保留切片之间的空隙；不做多段压缩、内容去重或跨分配合并。raw_start 是内部存储
身份，可以在回收时改变，不是语言可观察身份。每个引用都必须修补，共享关系保持。
不能遇到第一个切片就确定复制范围，后续存活切片可能扩展 lo/hi。
content 本身不扫描；临时分组与修补记录只在 GC 期间存在，无需持久 RawBytes 表。

这里保留的是全部存活视图需要的内容，因此依据是区间的**并集**，不是交集。
例如同一 raw_start 下存活 `[100, 140)` 和 `[130, 180)`，需要保留 `[100, 180)`；
若存活的是 `[100, 120)` 和 `[160, 180)`，精确并集为这两个区间，首版仍复制
`[100, 180)`，接受中间 40 字节的空隙。相比从 raw_start 复制到最大 end，
这也能回收所有视图都不再使用的前缀。

后续若有实际空间收益，可以按同一 raw_start 对存活区间排序，合并重叠或相邻
区间，分别复制精确并集的各个连续段。每个旧视图必定完整落在一个合并段内，
以该段的旧起点和新起点重定位；每段获得自己的 new_raw_start。同一旧分配此时
可以拆成多个新分配，不再要求整组只有一个新 raw_start。这样无需让一个 String/Bytes
视图跨多个存储段，也无需改变三偏移表示，但需要额外的区间排序和段映射。
这是后续可选优化，不作为首版验收条件；首版先采用上述包围区间策略。

精确并集方案的重定位规则如下，供后续实现沿用：

1. 只汇总外部存储的存活视图，按旧 raw_start 分组；内联值不参与。
2. 组内按 `(start, end)` 排序，合并重叠或相邻区间，得到互不相交的连续段。
3. 每段 `[seg_start, seg_end)` 只复制一次，记录目标起点 `seg_base`。
4. 对完整包含于该段的每个旧视图，设置
   `raw_start = seg_base`、`start = seg_base + old_start - seg_start`、
   `end = seg_base + old_end - seg_start`。

例如 `[100, 120)` 和 `[160, 180)` 可以压紧为目标中的两个 20 字节分配；
它们拥有各自的 raw_start，中间 40 字节不复制。若另有存活视图 `[110, 170)`，
则三个区间连成 `[100, 180)`，必须整体保留，不能删除该视图需要的中间内容。
同组区间排序及分组复制采用确定顺序，不依赖哈希表迭代顺序。
回收后再次切片、再次回收仍遵循同一规则；不能让旧 raw_start 的分组关系成为
语言可见的身份，也不能把这种按来源分组的共享误作按内容相等去重。

String 和 Bytes 都按字节长度采用相同的强制内联规则：`len < 16` 时内容直接存入
值的 payload，不分配外部内容，也不占用 content。这里 len 是字节数，不是字符数；
长度恰好为 16 时使用上述切片。内联只表示内容无需单独堆分配，包含该值的
record、数组或闭包本身仍可在 words 中。

构造、切片和转换得到不足 16 字节的结果时，复制这少量字节到内联表示，不保留
对原分配的引用；因此只剩短切片时，原大分配可以回收。较长视图继续共享内容。
具体标签、长度编码及对齐在落地时统一确定，不能直接把现有
STRINGS/BYTES 表项当成新的切片格式。

words 固定前缀默认不引用可回收内容。若常数采用字节内容池，则必须在 .telora
执行前明确封闭固定 content 前缀，整体保留且三个偏移不变，不参与区间裁剪；不能借普通
可移动字节分配绕过固定区免追踪条件。来源名称和 BOLs 仍按下文独立存储管理。

## 固定元数据前缀

RT 在执行任何 .telora 代码前，把需要放入语言堆的类型布局、GC 追踪描述及其他
常数元数据集中建立在 `[0, static_end)`，然后封闭此区。数据模块物化、property
计算、顶层值和 service 初始化产生的对象均从 static_end 之后分配。
边界以 word 为单位，满足 `static_end <= work_base <= words.len()`。

落地实现把类型追踪描述与反射镜像统一放入 Wasm 静态数据段，启动函数登记描述地址，
不再由 Host 的 prepare_collection 分配。所有命令（包括 service）共用此路径。
因此当前 words 的固定元数据前缀为空，即 static_end 为 0；永久元数据仍全部保留，
只是无需复制到 words 再保留一份。origin 则是 Wasm 静态镜像末端，与 Vec 边界不同。

固定区始终保留，不逐对象追踪、不进入转发表。成立条件是：

- 封闭后内容只读，不保存指向可移动区的 HeapId 或需要修补的对象表索引。
- 内部链接使用固定偏移、TypeId 等稳定身份，不保存 Vec 的物理地址。
- PropertyId 等稳定身份可以作为描述信息，但不会自动让属性结果成为固定区内容；
  其 `Id -> HeapId` 槽独立枚举为值根。固定区不承担这种可变槽的存储。

copy-collect 创建新 Vec 时整体复制固定前缀到相同下标，然后在其后复制存活对象。
免追踪表示偏移不变、无需遍历和修补，并非字节无需复制或物理地址永不改变。
Vec 扩容同样可能移动固定前缀的物理地址，访问仍须重新取得基址。

已嵌入 Wasm 静态数据段的反射镜像可以留在原处，无需为统一而复制第二份；它与
Vec 固定前缀都是永久保留区，但地址域不同。首版保留完整类型描述，不做类型裁剪。

## 保守根集合

固定前缀及 Wasm 静态镜像无条件保留。成功初始化后，对可移动区枚举以下根，
遍历其普通值引用和闭包捕获；遇到固定前缀引用直接保留原偏移，不继续追踪：

| 根 | 首版保留策略 |
| --- | --- |
| service handler | 保留 handler 及其 service、捕获环境和返回的准备结果 |
| 持久类型元数据值槽 | 枚举固定区之外由类型注册结构持有的堆值引用；不重复扫描固定类型描述 |
| 顶层初始化值 | 保留当前制品所有 Ready 的顶层值和已实例化泛型值槽，不分析哪些仅用于初始化 |
| property/check | 保留当前制品所有已求值 property 最终结果、checker 及必要的能力值 |
| 其他命令的结果 | eval/test 等使用各自已发布值或待执行 Test 根；不硬套 service 入口 |
| 尚待消费的反馈 | 保留初始化诊断与 debug 事件及其值引用，保持事件顺序和 Host 游标 |

根来自当前制品，不是全 workspace 的所有符号。未求值定义不是堆值，不为其凭空
分配根；失败初始化不发布 service 或设置可执行基线。

类型必须保活；“静态存储不搬移”不等于“不需要保留”。首版不裁剪当前制品的类型表、
布局或已生成的反射描述，TypeId 始终有效。具体区分：

- 当前类型骨架、成员名和成员类型关系编码在 Wasm 静态反射镜像中，随制品存活。
- 执行 .telora 代码前由 RT 建立的堆内常数元数据，迁入上述固定前缀，无需 GC 追踪。
- Type/TypeOf 物化后的语言值，以及 fields/variants 等反射操作构造的数组、成员
  描述和字符串值，会在语言堆中分配。当前这些反射结果按调用生成，不是全部缓存
  回类型表；通过普通值根保活，不能因为属于“元数据”就跳过追踪。
- property 的最终结果及其中的函数、容器和捕获也属于语言堆。
- 类型/property 注册结构若持有上述堆对象，其引用必须作为根枚举并在移动后更新；
  字段和 variant 属性同样适用。仅临时产生且无引用的反射结果可以回收。

实现须区分反射镜像地址、固定前缀偏移和可移动对象的 HeapId，不得把所有类型相关
地址一概视为静态。代码和静态镜像不参与语言堆复制；Vec 固定前缀只整体复制。

这使函数代码对顶层值的隐含引用也得到保护，首版不需要
`FunctionId -> [SlotId]` 描述，更不需要强行增加用户闭包的捕获字段。
以后若减少保留量，再增加该依赖描述，不影响当前引用表示。

初始化结束后的 property 链只需保留最终 reduce 结果；本策略仍可能因为顶层根
而间接保留 provider。允许这种冗余，不承诺回收全部初始化中间产物。

## 来源与堆外资源

来源记录继续是五个 u32：

```text
id, name_ptr, name_len, bols_ptr, bols_len
```

来源名称、BOLs 和记录缓冲区由独立所有者保留，不随语言 Vec 搬移或 truncate。
来源存储已与语言堆分离所有权，不能仅从根列表删除而仍使用语言 Vec 分配。
不改变 Host 只读视图及不可跨 Guest 调用缓存指针的约定。

静态源码与注入 source 的记录在初始化后保留；临时 parse 维持现有无注册来源的语义。
Loc 不变，来源表本身不把语言值反向保活。

Regex 等含 Rust 堆分配的资源不能当作普通 word payload 随便复制、截断。
首版保留资源表及其所有权处理：初始化存活资源保持有效，请求后缀资源先析构再
截断对应表，避免泄漏和重复释放。语言 Vec 不承担 Rust 对象的隐式析构。

## 初始化后的 copy-collect

1. 完成模块及 service 初始化，在没有外部语言值借用的边界回收。诊断/debug 若尚未
   消费，则作为根保留，不能因为提前回收而丢失反馈。Host 初始化前构造的输入必须
   先注入 demand；初始化后重新取得句柄，不能继续使用移动前的 Value 句柄。
2. 临时创建目标 words/content；原存储保持存活。将 words 的 `[0, static_end)`
   整体复制到相同下标，不扫描其内部。从上述全部值根通过显式工作队列追踪可移动对象。
3. 使用转发表保留共享与环，根据确定的类型布局修正对象内部引用；保留函数、类型
   和顶层槽等逻辑身份，不把移动后的物理位置变成新的语言身份。
4. 全部值追踪完成后，按 raw_start 汇总的包围区间复制字节内容，并修补所有存活
   切片的三个偏移；不扫描 content。更新 handler、Ready 槽、property/check 槽、
   对象表 payload 以及其他持久内部句柄。
   初始化专用 source/initializer 句柄不再使用的应显式清空，需要继续使用的必须更新。
5. 成功后替换旧 words/content，释放旧存储；static_end 不变，分别记录
   work_base、work_content_base 及各附属表基线。
   固定区引用保持原偏移，可移动区引用按转发表更新。

回收期间可以同时存在旧、新两套存储；“单 Vec”指结构化对象不再分 main/work 两套，
不是禁止独立的字节内容池。峰值包含旧、新 words/content、分组修补记录和转发表，
必须计入观察，不宣称 copy-collect 必然降低峰值。
回收失败不发布一半更新的服务；允许终止该次初始化，不要求复杂事务恢复。

第一版不用移动静态数据段。若有直接指向其中的语言常量，须用明确的静态引用表示，
或在初始化时物化进语言堆，不能把线性内存地址与 HeapId 混用。

## 请求与 reset

初始化前缀只读，包括已保留的 content。请求可以创建初始化内容上的切片，沿用
对应 raw_start，但不能修改原内容。前缀和永久根槽不能保存请求后缀引用。
RFC 0301 已移除 interpreter! 的反向缓存；其他路径仍须完成写入审计。

请求输出序列化到独立 ABI 缓冲区，诊断/debug 完成消费后，正常 reset 可以：

1. 释放请求期资源并恢复对象表、诊断表等附属状态的基线。
2. 分别将 words、content 截断到 work_base、work_content_base，保留各自 capacity
   给下次请求使用；后缀偏移只有在旧请求的所有引用失效后才能重用。
3. 重置请求 fuel、错误状态和输出游标，再接受下一次输入。

truncate 不会自动恢复 Wasm 栈指针、Rust 分配器状态、堆外 Vec 或所有权转移中的
Host 缓冲区，也不能让已增长的线性内存缩小。不能把它直接等同于完整 reset。

保守实施顺序是先在现有快照 reset 下完成偏移表示和移动回收，再替换正常完成请求
的 reset。fuel 耗尽、内存增长失败和其他 trap 路径，在证明可安全重入前，继续以
当前初始化快照重建实例。它是明确的异常恢复策略，不是两套语言对象布局的兼容路径。
快照完全退出应另有验证结论；不为追求“一行 truncate”削弱现有服务隔离语义。

## 实施计划

1. 列出持久引用、初始化根槽、来源分配及资源所有者；建立偏移访问边界，并统一
   RT 常数元数据先于所有语言值物化的构建顺序，封闭固定前缀。
2. 将 codegen/RT 的结构化语言引用迁移到单 words Vec，字节内容迁移到
   content 的 start/end/raw_start 切片模型；保留其余分类表，验证两种 Vec 强制扩容下的引用安全。
3. 加入保守根枚举和初始化后 copy-collect，验证重定位与身份。
4. 实现正常请求 truncate reset，保留经过验证的 trap 恢复边界。
5. 更新当前设计文档并测量 ontology；历史 RFC 只添加被本 RFC 覆盖的说明。

内部 ABI 在落地时递增，旧制品重新生成，不保留旧地址布局执行路径。
不在本 RFC 中实现精确 tree-shaking、请求期永久属性缓存、静态 property 专用接口
或删除现有动态反射能力。实施提交在独立远端分支推进。

## 验收

- 各命令在 .telora 执行前建立并封闭固定前缀；多次扩容及移动回收后，前缀内容和
  static_end 不变，其引用不进入转发表，不存在指向可移动区的隐藏链接。
- 强制多次 Vec 扩容后，数组/字典/record、字符串、闭包、Dyn 和来源诊断结果不变。
- 同组完整、重叠、不相交及多字节字符串切片在回收后内容正确；包围区间只复制
  一次，无用头尾被裁掉，中间空隙允许保留。不同分组不合并，三个偏移全部正确修补。
- 遍历时先遇到窄切片、后遇到向两端扩展的切片仍能正确保留内容；重复回收后仍正确。
- String/Bytes 的 0、15 字节结果不增加 content 长度，16 字节采用切片表示；
  长内容产生短切片时解除原引用，UTF-8 多字节内容按字节长度判断内联。
- 请求反复创建初始化内容的切片及新内容后，words/content 均恢复基线，
  初始化字节保持不变；范围溢出和非法 String 边界不会造成越界访问。
- service 捕获根之外、仅通过代码 Id 读取的顶层值，在初始化回收后仍有效。
- 通过 Array(Type)、字段/variant 索引动态查询已初始化 property，所得函数及其捕获
  在移动后仍有效；Property(P) 静态判断不进入求值。
- 共享对象、递归闭包和别名经过移动后保持语言身份及结构；所有持久槽无旧地址。
- 重复请求后逻辑 heap/table 长度恢复到基线，前缀不变，Regex 等资源不持续泄漏。
- 失败、warning、fuel/memory trap 后的后续请求与新建同基线服务一致；Host move/borrow
  缓冲区约定及来源定位不退化。
- Wasm/CLI 与独立 .telora 用例通过；ontology `check --lib`、world-model run/serve 通过。
- 记录初始化、回收、reset、请求耗时，Wasm 尺寸、线性内存与 Host RSS；同时记录
  copy-collect 的峰值和保守根保留量，不预设性能收益。

优先复用独立 .telora 用例；Rust 测试只承担扩容、重定位、资源生命周期等底层断言。
