# RFC 0311：动态输入诊断位置

- 状态：已实现
- 关联：RFC 0300（Host/Guest ABI 与来源位置）

## 动机与范围

解析后的动态输入值具有相对原始输入的字节跨度，但此前来源 ID 0 被整体视为
“无位置”，导致这些参数在 `fail!` 诊断中失去溯源。为每份动态输入建立 BOLs
并不必要；需要的是可供调用方定位参数的稳定 offset。

## 契约

保留全零跨度为无位置。动态输入使用来源 ID 0、非零跨度；诊断中的来源名
为 `<input>`，端点为 `line: 0`、`offset: <相对整个输入的 UTF-8 字节偏移>`。
普通源码及持久数据源的行号从 1 开始，offset 仍为行内 UTF-8 字节偏移。
`locs` 保持原顺序，规则位置与动态输入参数位置可以共存。不注册每份临时输入的
来源名称或行索引；服务请求正文也不留在服务基线中。

## 取舍与验收

不用零基行号与动态输入的 `line: 0` 混用；不增加新的位置记录形状。
全零跨度无法同时表示输入起点处的零宽位置，保持其“无位置”含义；对已解析
的非空参数不构成限制。验收覆盖源码与数据源的 1 基行号、动态输入参数的
`<input>`/`line: 0` 字节跨度、解析错误、重复解析，以及诊断捕获的顺序。

验收证据：telora-wasm 的来源范围和 transform service 测试、telora CLI 单测，
以及 lab-ontology 的 snapshot service 中 `fail!` 诊断均保留了上述位置结构。
