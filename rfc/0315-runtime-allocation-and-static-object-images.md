# RFC 0315：运行时独立分配、准确 GC 与初始化对象静态镜像

- 状态：Accepted，RFC PR #246 已合入；实现由 #245 跟踪
- 跟踪：[#245](https://github.com/hh9527/telora/issues/245)
- 日期：2026-10-23
- 基线：`a7f5e7f5`；RFC 0312、0313、0314

## 动机与范围

当前受管堆以一个 Vec<u64> 承载全部对象，自行维护页、大小类别、空闲槽与区间
合并。准确 mark-sweep 已支持执行期间回收，但初始化 copy collector、冻结前缀、
请求后缀 truncate 和 Host baseline 恢复仍共同决定存储生命周期。

本方案把存储分配交给 Guest 默认 Rust 分配器（语义上为 malloc/free），把对象
生命周期交给准确 GC。连续存储用于制品中的静态镜像，不作为动态执行的前提。
不引入用户可见可变状态、move、引用计数或 Host 执行语言回调。

#236 中默认 Vec 倍增的旧路径已被 RFC 0312 的 try_reserve_exact 替代；当前仍有
单连续分配、逻辑地址空间及失败报告限制。本 RFC 不承诺支持单对象超过 wasm32
分配上限，也不把 4 GiB 线性内存限额等同可用对象容量。

## 三个阶段

1. 初始化：数据实例、property、闭包和中间值是普通动态对象，独立分配并由准确
   GC 管理。成功初始化不要求通过重建实例或截断前缀获得内存正确性。
2. 制品生成：从选中的静态数据实例与 property 根遍历完整可达图，复制到连续
   空间并修补引用。保留共享关系和环，去掉不可达对象及不必要容量，得到根坐标、
   静态镜像与新的尾坐标。尾坐标如何用于后续分配等用途另行决定。
3. 正式运行：恢复后的静态数据实例、property 与 actor 注册长期根，保证使用期间
   整个可达图存活；请求和其他动态计算通过底层分配器分配，由准确 GC 管理。
   首版允许恢复后的对象统一参与 GC。静态图免于回收或重复扫描属于可延期优化。

普通制品、外部 source 初始化和 snapshot 制品共用上述语义。未固化的外部输入仍在
启动时计算；snapshot 固化 actor 实例并保留现有来源覆盖限制。未重整的活实例也能
直接执行，其长期对象通过根存活，不必伪装成静态地址区。

## 根与 actor 闭包

正确性语义是保活：在发布实例的使用期间，长期根及其传递可达的数据、property、
闭包和资源不得被回收。这里的“静态”描述初始化结果在制品中的保留与运行时用途，
不要求它具有特殊地址范围、分配方式或 GC 豁免身份。

根集合覆盖被发布的静态数据实例、具体 property，以及入口 actor 实例。
actor 包括 handler 捕获、函数依赖的顶层 demand、来源及资源恢复描述，不能只保存
handler 表面字段。现有 function_dependencies 与 Edge::Function 提供静态依赖证据。

首版保持现有已选执行闭包的初始化与 property 行为；不以本次存储改造暗中改变哪些
provider 会执行。普通 GC 可以保守保留 Ready demand；发布根的裁剪必须保证后续
函数访问不会重新执行已完成的初始化或访问被删除的值。不得以物理堆地址范围推断根。
初始化完成显式释放 initializer、注入暂存值等阶段性根，该操作不依赖 copy collector。

## 动态分配与引用

使用 Guest 默认分配器的 Rust alloc/dealloc 接口，记录原始 Layout 并正确配对释放；
不需要另引入 C runtime。对象零初始化与现有构造协议保持一致。

目标采用 Guest 线性内存地址作为动态引用；稳定的是 Guest 地址，不是 Host 借用的
物理指针。必须审计现有 ORIGIN、WORDS_VIEW 与 scratch 高位编码，统一处理静态、
动态和 scratch 引用，不能把高地址真实分配误认作 scratch。具体编码通过小原型冻结，
在实现记录中明确地址范围和限制；不为保留旧编码暗中增加分段 arena。

保留轻量分配登记，记录基址、范围、布局、扫描描述及 mark 状态。它负责 sweep
枚举、内部引用定位与预算，不负责大小类别、空闲链或页复用。内部字段指针及
数组元素指针必须定位到所属分配；零长度和 one-past 指针不得误保活相邻对象。
登记结构自身的分配不递归触发语言 GC。分配或登记失败不得留下未登记的存储。

## GC 与调用边界

保留准确 shadow roots、闭合类型扫描、pin generation、来源及 Regex 等资源追踪。
GC 仍在合法 safepoint 触发，不在未知局部状态的 malloc 内触发。sweep 释放死亡
分配及其资源；长期根保活恢复后的静态数据图，其引用按准确类型正常追踪。
连续镜像若作为一个整体装载，须明确 backing 的所有权，内部对象不得逐个 free；
若恢复为独立分配，则按普通对象登记与回收。两种装载方式都必须满足相同保活契约。

正常调用结束撤销调用根、消费并释放 ABI 缓冲、清理活动失败和已消费反馈。资源表
不靠恢复 baseline 或冻结索引永久保活。允许按阈值回收，不要求每请求执行全图 GC。

fuel、取消、诊断游标、Rust 临时资源与 trap 恢复仍需明确调用协议。trap 后禁止重入
失效实例，可从 actor 快照创建新实例；移除 truncate 不等于允许在 trap 后执行清理。

Raw/数组尾部追加必须保持已发布值不变。统一参与 GC 时，长期对象若保留了动态
后缀，必须准确追踪该引用，并测量额外保留成本。禁止长期存储尾部复用可作为控制
保留量的策略；不能把“静态图不得引用动态分配”作为统一 GC 的正确性前提。
后续若跳过静态图扫描，则必须证明或追踪其指向动态对象的边，避免漏标。

## 镜像重整与恢复

重整器读取存活运行时图，写入独立连续目标空间，转发表先发布再遍历，保持循环与共享。
修补根、普通引用、内部引用、闭包环境、Raw、Single、数组/Dict 存储和来源引用。
源码代码、TypeId、函数表等与匹配的 Wasm 制品绑定，不承诺跨编译制品任意迁移。

目标内保存坐标而非运行实例的 malloc 地址；恢复时按明确的重定位协议装载。静态
镜像拥有者保留对象边界及所需布局信息，不通过任意字节猜测对象。Regex 等外部 Rust
资源保存可恢复描述，恢复失败阻止 actor 发布。镜像生成不得修改正在使用的源图。

现有 copy collector 的扫描适配、转发表和容量压紧可用于重整器，但不再作为日常
回收或调用 reset 的必要步骤。运行时和重整器共用准确布局扫描，避免两套类型语义。

ABI 必须升级；旧制品明确拒绝。snapshot、数据模块镜像、transport、Host output 与
pin 协议同步，不能只改 heap::allocate 而遗留旧 words 地址解释。

## 配额与可诊断失败

分别报告动态有效分配、分配登记开销、静态镜像、scratch、累计分配与 Guest 线性内存。
底层分配器的隐藏开销和空闲空间不能伪称精确 managed 字节。managed 配额口径在实现
中固定并更新 GcConfig；Guest 总限额继续覆盖全部存储。

重整期源图和目标图同时存在，需单独测量峰值。free 允许空间复用，不保证 Wasm
线性内存缩页。分配、扫描、复制和回收在 Guest 受 fuel 执行；工作不得转移到不计量
Host 循环。危险分配前记录阶段、申请量、生效配额及错误分类，Host 能区别容量越界、
预算不足和分配失败，不依赖 panic 字符串跨 Wasm 传播。

## 实施计划

1. 独立交付 RFC，记录评审与授权；当前设计 SSOT 保持已实现事实。
2. 隔离原型冻结直接引用、scratch 和分配登记编码；验证内部指针、低配额与释放。
3. 实现独立分配与非移动 GC，迁移根生命周期、资源表及调用清理，移除连续堆依赖。
4. 实现从发布根重整静态镜像及恢复，覆盖数据模块和 actor 制品；同步 ABI。
5. 同步 LANGUAGE、IMPLEMENTATION、执行指南和统计文档，完成集成及真实模型对照。

首版以长期根和统一准确 GC 验证保活；静态图免扫描、免回收等优化不作为实施前置
条件或本次完成要求。

所有变更在工作分支；构建与实验产物在 /tmp，不替换消费方使用的工具。阶段提交
按会话授权执行，合入 main 另行授权。RFC 先提交，再实施。

## 可执行验收

- 分配：0/1/大对象、对齐、零初始化、释放与地址复用；内部指针定位、边界和悬空
  pin 拒绝；故障注入验证分配登记失败不泄漏。覆盖 scratch 与真实地址编码边界。
- GC：自动关闭、正常间隔、每 safepoint 强制收集结果一致；嵌套值、闭包、循环、
  Raw、Single、Dict、部分输出及动态来源均覆盖，死亡资源仅释放一次；恢复后的
  静态数据图参与强制 GC 时，长期根及其传递依赖保持有效，释放根后按所有权回收。
- 调用：大量成功/失败交替请求不依赖 truncate，已消费反馈不持续保活；已发布值
  保持不变，长期对象的额外保留可解释；trap/fuel 后禁止重入且从快照恢复输出一致。
- 镜像：根可达对象完整，共享与环不变，未引用初始化垃圾不进入镜像；顶层 demand、
  property 与函数依赖恢复后可用，provider 不重复执行；重整不修改源 actor。
- 制品：源码运行、普通 build、snapshot build、独立 runner、HTTP/JSONL 输出一致；
  静态数据与动态数据跨边正确，旧 ABI 拒绝，异常和截断镜像稳定拒绝。
- 资源：低 managed/Guest 配额、整数溢出、失败分类、fuel 停机；无成功半成品发布。
- 性能：同源码、参数与输入至少三轮对照，覆盖小对象、长内容、稀疏/稠密数组与
  ic-model；报告初始化、正式请求、重整与恢复各阶段墙钟、fuel、分配、GC、镜像大小
  和 Guest 高水位。调查明显回退，不以代码减少替代性能证据。
- 完整性：workspace、全部语言 fixtures、build/run/serve smoke、格式与规模检查；
  归档具体命令及既有失败。RFC 阶段仅做内容、链接和 diff 检查。

## 备选与延期

- 静态图免扫描、免回收：属于性能优化；先以长期根和统一准确 GC 满足保活语义。
  引入时另行验证静态到动态的引用边与镜像 backing 所有权。
- 分段 words arena：保留了自建分配和地址转换复杂度，不作为本方案默认路线。
- 每请求全图 GC：不是正确性要求，先使用阈值策略，以实测决定额外边界收集。
- 引用计数、move、用户可见可变状态：不在范围。
- 新尾坐标的后续用途、memory64 与单对象超大存储：后续讨论。
- 快照跨代码版本兼容与通用对象数据库：不在当前 ABI 契约内。
