# RFC 0319：类型信息的封闭缓存

- 状态：工作分支探索

## 动机与范围

构建期程序重复计算同一类型的标识和描述，当前应用只能使用字符串键或数组扫描。类型元数据已带有精确身份，标准库提供类型专用缓存，将类型身份直接作为内部索引。能力不依赖 Service，也不引入外部输入。

## 接口与语义

```telora
use std::type_memorizer as memo;

def info: memo::TypeMemorizer(String) = memo::type_memorizer(fn(ty: Type) {
    # 根据 ty 计算类型信息
    "description"
});
# 同一实例、同一类型复用成功结果
memo::computed_with_type(info, Int.type)
```

```text
type_memorizer: for(R) Fn(Fn(Type) -> R) -> TypeMemorizer(R)
computed_with_type: for(R) Fn(TypeMemorizer(R), Type) -> R
```

计算函数在创建时固定，应用观察到的是 Type → R 的函数。每次构造得到独立缓存；共享同一个值共享实现资源。成功结果按精确类型身份缓存，具名 newtype 即使底层表示相同也不混用。缓存没有成员访问、容量、计数、命中检测、清除或修改接口，私有槽位只由查询闭包捕获。公开表示只包含查询函数；函数沿用语言已有的身份规则，函数身份不表示缓存内容或命中状态。

计算应只依赖类型和不可变闭包捕获的语义输入。调用者不能在每次查询时更换计算函数，否则返回值会依赖调用历史。诊断、执行成本和分配不属于缓存的值接口；首版不将 memoization 声称为适用于任意带诊断行为函数的透明编译器优化。

同一实例内递归请求 Pending 类型时产生明确的循环依赖诊断。计算的语言失败不缓存，清空该 Pending 槽后传播原失败；后续查询可以重试。引擎 trap 终止当前执行，不转换成可恢复的缓存结果。

## 实现与生命周期

首版用当前封闭类型空间的内部 TypeId 索引私有槽位，查询 O(1)，初始化和空间 O(封闭类型数 × 槽宽)。不生成字符串 key，不开放整数 TypeId。槽位使用 Empty／Pending／Ready(R) 的普通类型化数组，复用现有精确 GC、共享保持和 snapshot 机制。应用无法从查询闭包提取其环境。

缓存随闭包可达性管理。构建期只输出计算结果时，缓存不是运行程序的根；显式把 memorizer 保留在运行程序中时，其固定计算函数和缓存也必须保留。不同 Session 不共享状态。首版不加入全局缓存、淘汰策略或并发协议。

## 备选方案

通用字符串键缓存延后；不要求模型用递归哈希重新计算已有类型身份。每次查询传入 calc 的方案放弃，因为相同 key 配合不同 calc 会让返回值依赖历史。稀疏或分页槽位在测量类型空间和 GC 开销后考虑。

## 验收

- 相同类型的再次查询跳过计算；不同名义类型和不同实例相互隔离
- GC 后，字符串、数组和记录等成功结果保持正确
- 同 key 的递归依赖明确失败，语言失败后重试不产生伪循环
- 分阶段构建恢复后，已缓存和未缓存的 key 均正确
- ontology 分别测量显式 World 和类型信息缓存的收益，不混淆两种机制
